O motor de e-mail do Operações.

Sim, existe. Um pipeline duplo: produção fala com a fila de e-mails legada (REST V2 / Seahorse) via API autenticada com HMAC, e o ambiente local desvia tudo para o MailHog. Este artefato mapeia o caminho completo — de quem dispara até a entrega — e o que você precisa saber para trabalhar com ele.

RestV2EmailQueue MailHelper HMAC SHA-256 Laravel 8 · PHP 7.4
Entrada única
1

MailHelper::send() é o único gateway. Nada de Mail::send() solto em produção — todo envio passa por ele e decide o destino por ambiente.

Rota de produção
REST V2

POST síncrono em /mensageiro/email com assinatura HMAC SHA-256, chaves do .env e remetente definido por apelido na base legada msg.emails_remetentes.

Rota local
MailHog

Em local, o e-mail vai para um dev fixo via SMTP local (mailhog:1025). Nada sai de verdade; você inspeciona no UI do MailHog.

01 / Pipeline

O caminho do e-mail, do clique à fila.

O disparo nunca é direto: um repositório, helper ou command chama o gateway, que renderiza o mailable e decide a rota pelo ambiente.

1 Disparo

Repositories, Helpers, Controllers e Commands chamam MailHelper::send($emails, $mailable, $subject?, $sender?).

→
2 Gateway MailHelper

Converte destinatários em array, chama build() do mailable para capturar o subject se não foi passado e decide a rota por app()->environment().

→
3 Render do corpo

Em produção, $mailable->render() gera o HTML da view Blade (resources/views/emails/**) que será enviado como corpo.

→
4 Fila legada

O RestV2EmailQueue monta os parâmetros, assina com HMAC e faz POST para a fila msg.fila_envio_emails no SQL Server legado.

→
5 Entrega

A fila legada despacha o SMTP. A resposta traz o ID do agendamento: "EMAIL AGENDADO: ID: 12345".

Rota alternativa — ambiente local
Se app()->environment('local')

O MailHelper ignora a fila e usa o Mail nativo do Laravel via SMTP apontando para o MailHog (MAIL_HOST=mailhog, porta 1025). O destinatário é substituído por william.pinheiro@eletromidia.com.br — o dev principal — para testes.

Se qualquer outro ambiente

Sobe pela RestV2EmailQueue: renderiza o HTML do mailable, valida/deduplica destinatários, monta CURLFile para anexos e envia via cURL para o REST V2. Sem exceção — é o caminho único em produção.

02 / Ambientes

Dois comportamentos, uma assinatura.

O mesmo código renderiza o mesmo e-mail; o que muda é o transporte e o destinatário.

Produção · REST V2 Email Queue

Fila corporativa com autenticação por chave

  • Envio síncrono via cURL (sem fila do Laravel — QUEUE_CONNECTION=database não participa do e-mail).
  • Autenticação por pubkey + seckey (HMAC SHA-256), lidas de USER_EMAIL_QUEUE_PUBLIC_KEY e USER_EMAIL_QUEUE_PRIVATY_KEY no .env.
  • Remetente é um apelido cadastrado na tabela legada msg.emails_remetentes (default: MAILSENDER).
  • Destinatários: array JSON de e-mails válidos (FILTER_VALIDATE_EMAIL + unique()). Zero e-mails válidos = exceção.
  • Anexos: CURLFile + mime por finfo, chaveados por nome do arquivo.
  • Sucesso retorna o ID da fila: EMAIL AGENDADO: ID: <id>.
Local · Laravel Mail + MailHog

Caixa de teste que nunca entrega

  • Dispara via Mail::to($emailDev)->send($mailable) com SMTP mailhog:1025 (sem TLS, sem credenciais).
  • Destinatário fixo: william.pinheiro@eletromidia.com.br — você nunca vê o e-mail "real" do fluxo.
  • Interface do MailHog em http://localhost:8025 (porta padrão do container) para inspecionar HTML e anexos.
  • Importante: não testa o fluxo de assinatura, a validação de apelido do remetente nem a fila legada.
03 / Segurança

Como o REST V2 confia no seu pedido.

Cada chamada é assinada com HMAC SHA-256 usando a chave privada — nada de segredo no payload.

Assinatura HMAC (gerada em generateSecretKey())

ksort($params); $token = hash_hmac( "sha256", strtolower($method) . $path . serialize($params), $this->privateKey );

Headers enviados no cURL

Authorization: Token {pubkey} Public-Key: {pubkey} Client-SID: {session_id} Client-RemoteAddr: {REMOTE_ADDR} Client-UserAgent: {HTTP_USER_AGENT} Client-Referer: {HTTP_REFERER}
Payload

POST em REST_V2_URL + /mensageiro/email

Parâmetros montados em saveToQueue() — a ordem importa, porque ksort e serialize fazem parte do token:

  • remetente — apelido válido na tabela msg.emails_remetentes (padrão MAILSENDER).
  • destinatarios — JSON array de e-mails validados e deduplicados.
  • assunto — subject capturado do mailable (ou passado explicitamente).
  • pubkey — chave pública do .env (duplicada no header).
  • corpo — HTML renderizado do mailable.
  • seckey — token HMAC calculado com a chave privada.
Falhas e log

O que acontece quando dá errado

  • Erro de cURL → exceção "CURL ERROR - {errno}".
  • Resposta vazia → exceção "ERRO NA CHAMADA DO REST_V2 MENSAGEIRO".
  • JSON inválido ou status != true → OperationalLogHelper::error('emails', 'restv2-queue', ...) com params (sem chaves), resposta e URL, e exceção lançada.
  • Nenhum destinatário válido → exceção "Nenhum e-mail valido para destinatario".

Rastreie falhas pela tag emails no log operacional — é o ponto de partida de qualquer investigação de e-mail não entregue.

05 / Quem dispara

Os pontos de entrada do motor.

Nenhum deles fala com a fila diretamente — todos passam pelo MailHelper. É o que garante a troca de transporte sem tocar em regra de negócio.

Fluxos de chamado

Tickets

TicketsRepository (abertura, liberação, atribuição a terceiros), TicketMastersRepository (fechamento) e TicketHelper (N3, empresa terceira, rota de técnico).

Qualidade e projetos

Inspeções

QualityTicketHelper avisa a equipe de qualidade; ProjectWorkInspectionsRepository avisa sobre vistoria de obra concluída.

Auth e feedback

Autenticação + NPS

LoginController envia o código de acesso; ForgotPasswordController o link de reset; RatingsRepository dispara o NPS.

06 / Guia prático

Como enviar um e-mail novo.

O padrão é fixo: mailable + view + chamada única ao gateway. Não reinvente o transporte.

1 · Crie o mailable (padrão Laravel, PHP 7.4-safe)

php artisan make:mail ExemploMail // app/Mail/ExemploMail.php public function build() { return $this->subject('Assunto do e-mail') ->view('emails.exemplo'); }

2 · Crie a view em resources/views/emails/

{{-- resources/views/emails/exemplo.blade.php --}} <h1>Olá, {{ $nome }}!</h1> <p>Seu chamado {{ $codigo }} foi atualizado.</p>

3 · Dispare pelo gateway (nunca Mail::send direto)

use App\Helpers\MailHelper; use App\Mail\ExemploMail; MailHelper::send( ['cliente@eletromidia.com.br', 'sup@x.com'], new ExemploMail($ticket) ); // sender opcional: MailHelper::send(..., 'SUPORTE');

4 · Teste e valide

# Ambiente local: confira em http://localhost:8025 (MailHog) # O e-mail vai para william.pinheiro@eletromidia.com.br # Se precisar validar remetente, confira o apelido na tabela legada: # msg.emails_remetentes (coluna "apelido")

08 / Armadilhas

O que morde quem não conhece o motor.

Lições colhidas do código — evite repetir o erro.

Envio síncrono e sem timeout

O cURL da fila roda CURLOPT_TIMEOUT = 0 (sem limite) no ciclo da request. Se o REST V2 estiver lento, a request do usuário espera junto. Não existem jobs de e-mail aqui — a fila do Laravel não participa.

Remetente inválido quebra o envio

MAILSENDER precisa existir como apelido na tabela legada msg.emails_remetentes. Um apelido novo exige cadastro no legado antes de usar setSender().

Local mascara destinatários

Em local o e-mail vai sempre para o dev fixo. Testar "quem recebe o quê" em local é impossível sem mudar o comportamento — valide regras de destinatário com testes, não no MailHog.

Chaves são compartilhadas e globais

Todos os envios usam as mesmas chaves do .env. Rotação de chave afeta o sistema inteiro de uma vez, e o token HMAC muda com qualquer alteração de payload — params e token andam juntos.

Não confunda com o RestV2Helper

O RestV2Helper (e o RestWSClient) é outro cliente REST V2 usado para tickets, HubSpot e WhatsApp — não é o motor de e-mail. O motor de e-mail é só RestV2EmailQueue + MailHelper. As notificações Laravel (MaintenanceNotification, ReportNotification) também são canais separados (database/Slack) e não passam pela fila de e-mail.

Resumo para o dia a dia.

Existe um motor de e-mail: MailHelper::send() é a porta de entrada, o RestV2EmailQueue é a fila de produção assinada por HMAC e o MailHog é a caixa de testes local. Para enviar um e-mail novo: crie o mailable, a view em resources/views/emails/ e dispare pelo gateway — nada de Mail::send solto. Em caso de e-mail não entregue, procure a tag emails no log operacional.
